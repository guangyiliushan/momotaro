# 重建与恢复 {/* #rebuild-and-recover */}

检索索引是派生物：里面的内容全都能从规范存储重新建出来。这一页是它打不开时的恢复路径——以及让脚本安全依赖的退出码规则。

## 恢复三步 {/* #walk */}

1. **先问工作区它怎么想：**

   ```bash
   momotaro doctor
   ```

   健康的工作区说 `workspace is ready`。不健康的退 `1`，并且——当问题出在索引上时——点出那条修好它的命令。

2. **重建：**

   ```bash
   momotaro rebuild-index
   ```

   旧索引被丢弃，从规范存储重新建出。规范数据分毫不动。如果被替换的是一份陈旧索引（旧 schema、截断的文件、缺失的段，或空壳目录残留），命令与它的 JSON 报告会**明说**——丢一个派生物不要紧，悄悄丢它才是"我的结果怎么变了"之谜的源头。

3. **确认：**

   ```bash
   momotaro search "之前查不动的那个查询"
   ```

## "从未索引"不等于"坏了" {/* #never-indexed */}

从未索引过的工作区是*就绪*的，不是 invalid——还没出事。对它跑 `search` 会提示你先跑 `index`。把两种状态分清：`doctor` 失败意味着哪里真有问题；新工作区里 `search` 找不到索引，只是天还没亮。

而 `index` 修不了丢失或打不开的索引——它只追加库里没见过的东西。当索引本身是病灶时，命令是 `rebuild-index`——提示会明说这一点，而不是安安静静地索引零个文件。

## 给脚本的退出码 {/* #exit-codes */}

- `0` 成功、`1` 失败——只有一处刻意的例外：`doctor` 以**健康**为准入门槛，未初始化或 invalid 的工作区即便报告打印正常也退 `1`。（`doctor --coverage` 是*报告*不是检查：只要日志读得到就退 `0`，包括"还什么都没发生过"的情况，此时 `--json` 打印 `null`。）
- 用法错误（未知参数或子命令）退 `2`——而且连 `--json` 也拿不到 JSON 体，因为解析在程序自己的错误出口运行之前就失败了。
- `index` 的逐文件错误**不会**让整批失败：摘要里写着 `N errors`（N > 0）也照样退 `0`，因为每个失败都被记录在案、批次本身完成了。
