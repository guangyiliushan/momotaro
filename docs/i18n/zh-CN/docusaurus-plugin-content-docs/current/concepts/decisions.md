# 设计决策 {/* #decisions */}

这里收集的是用户能亲身感受到的选择——产品的形状，而不是内部实现。每一条给出决策、理由与付出的代价。每个决策怎么实现是工程问题，工程会变；写在这里的，是你能够依赖的东西。

## 确定性优先 {/* #deterministic-first */}

**决策。** 检索、分块与引用校验全程不引入模型。模型只在真正需要判断的地方被调用。

**理由。** 可复现、能离线、成本诚实：一次搜索不花钱，同一个查询在任何机器上给出相同结果。

**代价。** 0.x 不做语义改写——你的用词与文档用词不重合时，词法检索就是会漏。逃生门（向量检索）被有意推迟到证据要求它的那天，而不是"以防万一"先装上。

## 每个答案可追溯 {/* #traceable */}

**决策。** 答案携带引用；每条引用在你看到答案之前都与记录下来的修订核对过；失败就显示为失败。

**理由。** 可信的系统不能要求你相信它。字节可以核对；模型的记忆不行。机制细节在[检索与引用](retrieval-and-citations.md)。

**代价。** 有些答案读起来不那么"顺"，因为没通过校验的论断不会被顺滑掉——证据断了，系统就停口，哪怕模型当时说得很自信。

## 人是作者 {/* #people-author */}

**决策。** 只有人写的东西是事实。agent 产出在被收下之前始终是"待议"，任何东西都不会被自动写进你的笔记。

**理由。** 书桌是你的：证据、判断与署名权都留在人手里。一张[启发卡](../glossary.md#spark)只有经人手才成为库的一部分。

**代价。** 牺牲便利——"帮你自动归档"式的自动化，设计上就不存在。

## 本地优先，零遥测 {/* #local-first */}

**决策。** 工作台就是你机器上的文件加一个本地数据库。开局不需要账号；永远没有遥测。

**理由。** 阅读与写作的轨迹就是科研数据，科研数据属于研究者。关于你的库的一切，不被收集、不被计数、不发回任何地方。

**代价。** 0.x 没有云同步、没有跨设备魔法——搬迁工作区就是复制一个目录。这是为可验证性与隐私付出的有意代价。

## 一座库，不是两座 {/* #one-library */}

**决策。** 笔记与论文共用一份索引、一份结果列表。

**理由。** 两类材料并排时最有用——论文的命中与反驳它的笔记，出现在同一个排序视图里。把它们拆成两次搜索，恰好会藏起工作台存在的意义：材料之间的相互照见。

**代价。** 要排序滤掉的噪声更多；[检索与引用](retrieval-and-citations.md)里的来源加权就是补偿。

## 归档不是删除 {/* #archive-not-deletion */}

**决策。** 退役的材料进归档；销毁是单独的、显式的一步。迁移在动手之前先留备份。

**理由。** 科研数据会累积起以后才显出价值的历史——旧批注、被替代的修订。不可逆是敌人；一个能悄悄弄丢你工作的系统，不配拿着你的工作。

**代价。** 磁盘占用会一路增长直到你亲自决定减负；整理是人决定的事，不是后台"清理"。

## 没有产品 Web 后端 {/* #no-web-backend */}

**决策。** 桌面与命令行就是产品。没有服务端产品，没有公司手里的文库副本。

**理由。** 工作台跟着研究者走——文件本来就在你的机器上；后端只会把真相搬离它们。

**代价。** 没有"打开浏览器随处用"的故事；分享要靠你自己发布文件。两者都是未来的、要显式讨论的话题，而不是默认开启。
