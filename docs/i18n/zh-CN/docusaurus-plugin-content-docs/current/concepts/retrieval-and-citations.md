# 检索与引用

这是工作台正中央的那个循环：查询走进一份词法索引，最好的材料带着排序回来，答案里的每一条论断都能指回可以被检查的字节。

## 一次提问，从头到尾

把正中央的循环展开成一条序列：

```mermaid
sequenceDiagram
    actor U as 你
    participant R as 检索
    participant C as 上下文构建
    participant M as 模型端点
    participant V as 引用校验
    U->>R: 提出一个问题
    R->>R: 对词法索引打分
    R->>C: 排好序的块
    C->>M: 一次调用，预算之内
    M->>V: 带引用的答案
    V->>V: 引文对照记录字节
    V->>U: 答案，失败被标出
```

到那唯一一次模型调用为止，一切由代码完成；之后的检查也由代码完成——模型既不决定取什么，也不认证自己的答案。

## 一份索引，同时罩着笔记与论文

笔记与论文住进同一份词法索引，于是一次查询返回混合结果——论文的命中旁边就是谈论它的那篇笔记，笔记的命中也能带出它的论文。结果按来源加权排序：你自己写的东西分量高于论文，论文高于网页副本。同库检索正是设计的目的——两类材料互为对照——而不是把两次搜索缝在一起。

## 确定性优先

搜索不花模型一分力：打分是词法的，中日文文本原生分词。这就是搜索快、能离线、且可解释的原因——也是它每台机器、每次运行都一样的原因。

## 从命中到块

检索的单位是[块](../glossary.md#chunk)。每个命中都是某个[来源修订](../glossary.md#source-revision)里的一块——正因如此，[引用](../glossary.md#citation)才可能存在。命中不是答案；它是带着位置的证据。

## 引用五元组

答案里的每条论断都能沿着五元组回查：来源键、修订、修订内的定位、引文原文、引文的哈希。它们合起来把论断钉到字节上——不是钉到某份"大概存在"的文档，而是钉到这次运行发生时确实存在的确切文字。

## 答案由什么构成

答案是一串**被引用的跨度**，不是自由散文。模型只挑选回答问题的那些跨度，别的什么都不写；把它们连起来的措辞取自一个固定的连接词集，它什么都不声称——不声称句子边界，也不声称跨度之间的关系。那些是源自己要说的事，而源在它自己的文字里说。

这正是论断可被核对的原因。答案里每一个事实字节都来自某个跨度，而每个跨度都能在记录下来的修订里被找到。模型写出的、却不属于任何跨度的句子，没有地方可去。

## 校验是一等状态

答案展示之前，它的每个跨度都要与记录下来的修订核对：引文必须一字不差地在那里。校验失败的跨度会被醒目地报为失败——绝不悄悄丢弃——因为模型的记忆不是证据，记录下来的字节才是。校验失败是设计好的结局，不是错误状态。

结果有三种，差别要紧：

| | 含义 | 你看到什么 |
|---|---|---|
| **已定位** | 引文确实在记录下来的字节里，一字不差。 | 正常展示。 |
| **未能定位** | 无法核对，或字节对不上。 | 标出并单独呈现——绝不包装成结论。 |
| **源与源不一致** | 两个源对同一段跨度说法不同。 | 两边都给，并注明各自出处。 |

**没有经过核对的跨度根本不会被渲染**：不存在"半核对"的答案。

**「已定位」说了什么、没说什么。** 它说的是这段引文指向记录修订里的真实字节。它**没有**说这些字词支持它们被拼成的那句话——没有机器会去读那一层。界面上的措辞是**引自**，不是**已核验**：断言的强度，恰好等于实际执行过的那次核对的强度。

## 什么能到达模型

检索决定什么值得展示；[上下文范围](../glossary.md#context-scope)决定什么可以进入模型的上下文：P1 是已绑定项目的材料（没绑定时是整个笔记库），P2 是其余部分。这个划分只影响模型看到什么——永远不影响检索记录了什么。

## 回放

查询、证据、提示、模型的回答与校验结论被一起记录成一段[回放](../glossary.md#trace)。回放不了的[运行](../glossary.md#run)，是信不过的运行。
