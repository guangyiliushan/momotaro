# 引用付きで質問する {/* #ask-with-citations */}

`ask` はコード側で検索し、コード側でコンテキストを組み、モデル呼び出しを多くとも 1 回行い、答えをバイトに固定します。このページでは返ってくるものと、その周りの 3 つのつまみを扱います。

## 返ってくるもの {/* #what-comes-back */}

- 答え。番号付きの引用を伴います；
- [ラン](../glossary.md#run) id、そしてそのまま貼れる `momotaro trace <run_id>`；
- 各[引用](../glossary.md#citation)の検証判定——失敗した引用は失敗として示され、静かに捨てられることはありません。

ランが失敗した場合、コマンドは `1` で終了します——それでも答えと明示的な失敗マークは表示され、スクリプトと人間が同じものを見ます。

## セッション {/* #sessions */}

`--session` なしでは、質問のたびに新しいセッションが開きます。続けるには、その id を渡します（前の答えの両方の出口が id を印字します）：

```bash
momotaro ask --session <session_id> "ノイズ項はどうですか？"
```

id は実在するセッションを指さなければなりません——打ち間違いはエラーであり、黙って新しい会話にはなりません。前のラウンドがクラッシュで中断していた場合、次のコマンドがまず古いラウンドを掃除してから続きます。手で片付けるものはありません。

## 再生安全な再試行 {/* #retries */}

再試行する自動化は、クライアントリクエスト id によって「ちょうど 1 回」の振る舞いを得ます：

```bash
momotaro ask "…" --client-request-id retry-7 --allow-network
```

同じ id の再生は**同じ**ランを返します——重複した作業も、重複した課金もありません。同じ id に違うリクエストを組み合わせると名前を挙げて拒否され（冪等キーの衝突）、空の id も拒否されます。id には「試行」ではなく「論理リクエスト」の名前を付けてください。

## ネットワークゲート {/* #network */}

質問はモデルプロバイダーと話すので、ネットワークが明示的に許可されるまで拒否されます——コマンドラインの `--allow-network`、または設定で一度だけ：

```toml title="momotaro.toml"
[policy]
allow_network = true
```

拒否は**接続の前**に起きます：何も記録されず、終了コードは `1`。`--no-llm` は `ask` 自体を拒否します——モデルなしで答える中間モードはありません。

## 引用検証が失敗したとき {/* #failure */}

引用が失敗すれば、ランは失敗します。それが設計です。答えは失敗を隠すように「掃除」されず、トレースは記録されたリビジョンで見つからなかった引用文を正確に示します。失敗は材料についての信号として扱ってください——コマンドについての信号ではなく。検証は仕事を果たしたのです。
