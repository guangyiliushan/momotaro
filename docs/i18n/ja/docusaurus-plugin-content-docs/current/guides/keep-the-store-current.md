# ストアを最新に保つ {/* #keep-the-store-current */}

保管庫は決して静止しません。ファイルは編集され、名前を変え、消え、外から放り込まれます。ストアは 2 つのコマンドで誠実さを保ちます——どちらも同じ原器を共有します。保管庫全体の一回の走査であり、実際に何が変わったかは各ファイル自身のバイトが決めます。

## 見張る {/* #watch */}

```bash
momotaro watch
```

活発に書いている時間帯のための常駐プロセスです。まずファイルウォッチャーを開き、それから一回の全身走査を走らせます——起動中に起きたことを何ひとつ取りこぼしません。あとは `Ctrl-C` で止めるまでイベントをさばき続けます。

**イベントはヒントであり、決して真実ではありません。** ファイルシステムのイベントが何を主張しようと、ウォッチャーはそれを「そのパスを再スキャンせよ」と読み替え、判断は再スキャンに委ねます。さらに 24 時間ごとに全体を再照合し、プラットフォームがイベントの取りこぼしを報告したら即座に、ひと山のイベントが 256 パスを超えたら（イベントの嵐）やはり再照合します——その時点では 1 回の全身走査のほうが安く、確実にできる唯一の手段だからです。

`--json` では各行が `kind` 付きの 1 オブジェクト（`batch`、`reconciled`、`degraded`、`network_volume` など）になり、スクリプトが見分けられます。ネットワークドライブ上の監視はその旨を告げ、リアルタイム性は**約束されません**。

## 照合する {/* #reconcile */}

```bash
momotaro reconcile
```

必要なときの一回の全身走査——ウォッチャーが起動時・毎日・取りこぼしの後に走らせるのと同じ原器です。ストアと保管庫がずれた疑いがあるときは手で走らせてください：ウォッチャーが止まっている間に消されたファイル、見逃した改名、途中で中断したインデックス。

`--json` では 1 つの要約オブジェクトを印字します：`batch_id`、`scanned`、`changed`、`removed`、`events`。触ったファイルはすべて監査ログに記録され、その回が何をしたか後から確認できます。

## どちらをいつ {/* #which */}

- ほぼ毎日書いていて、保存に合わせて検索結果を新鮮に保ちたい？ `watch` を常駐させてください。
- しばらく離れていた、あるいはツールが動いていない間にファイルに触れた？ `reconcile` を 1 回。
- スクリプトと他のマシン：`reconcile` が安全で有限な呼び出しです。`watch` は止めるまで走り続けます。

## 中断は安全 {/* #interrupt */}

どちらのコマンドも——最悪の瞬間に止めても——後片付けは不要です。各ファイルの行はそのデータと一緒にコミットされるので、途中で中断したバッチは単に「まだ起きていない」ことになり、次の起動時の照合が差分を埋めます。状態を手で直す必要は決してありません。
