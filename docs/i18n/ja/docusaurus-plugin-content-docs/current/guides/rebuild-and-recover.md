# 再構築と復旧 {/* #rebuild-and-recover */}

検索インデックスは派生物です。中身はすべて、正典のストレージから組み直せます。このページは、インデックスが開けないときの復旧路——そしてスクリプトから安全に使うための終了コードの規則です。

## 復旧の 3 ステップ {/* #walk */}

1. **まずワークスペースに聞きます：**

   ```bash
   momotaro doctor
   ```

   健全なワークスペースは `workspace is ready` と答えます。不健全なら `1` で終了し——問題がインデックスにある場合は——直すコマンドを名指しします。

2. **再構築：**

   ```bash
   momotaro rebuild-index
   ```

   古いインデックスは捨てられ、正典のストレージから組み直されます。正典データには手が触れません。陳腐化したインデックス（古いスキーマ、途中で切れたファイル、欠けたセグメント、空の残骸ディレクトリ）が置き換えられた場合、コマンドとその JSON レポートが**そう告げます**——派生物を失うのは構わない。静かに失うことが「結果がなぜ変わった」を謎にするのです。

3. **確認：**

   ```bash
   momotaro search "さっき失敗したクエリ"
   ```

## 「未インデックス」は「故障」ではない {/* #never-indexed */}

一度もインデックスされていないワークスペースは*レディ*であって、invalid ではありません——まだ何も悪くないのです。そこで `search` すると、先に `index` を走らせるよう告げられます。2 つの状態を混同しないでください：`doctor` の失敗は何かが本当に悪いという意味。新しいワークスペースで `search` がインデックスを見つけないのは、ただ朝が来ていないだけです。

そして `index` は、失われた・開けないインデックスを修理できません——ストアが見ていないファイルを追加するだけだからです。インデックス自体が病巣のときのコマンドは `rebuild-index`——静かにゼロファイルをインデックスするのではなく、メッセージがそう告げます。

## スクリプトのための終了コード {/* #exit-codes */}

- `0` 成功、`1` 失敗——ただし 1 つだけ意図的な例外があります：`doctor` は**健全性**をゲートにするので、未初期化や invalid のワークスペースは、レポートが正常に印字されても `1` で終了します。（`doctor --coverage` は*レポート*であり検査ではありません：ログが読める限りいつでも `0` で終了し、「まだ何も起きていない」場合も含みます。そのとき `--json` は `null` を印字します。）
- 使い方の誤り（未知のフラグやサブコマンド）は `2`——`--json` でも JSON ボディは得られません。解析が、プログラム自身のエラー出口より先に失敗するからです。
- `index` のファイル単位のエラーはバッチを**失敗させません**：`N errors`（N > 0）と書かれた要約でも `0` で終了します。すべての失敗が記録され、バッチ自体は完了しているからです。
